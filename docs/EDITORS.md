# Редакторы контента

Игра стартует со сцены `res://menu.tscn` (`scripts/menu.gd`). Конструктор в этот старт не входит: его окно поднимает автозагрузка `ConHotkey` (`scripts/con_hotkey.gd`). Плагин редактора Godot `addons/loc_bridge` включён в `project.godot` и работает только внутри редактора Godot, не в запущенной игре.

Все записи `data/*.json` ниже идут через `DataLoader.save_json`. Для `locations.json` запись пустого словаря и словаря короче двух ключей (если файл уже есть) отклоняется. Для `world_terrain.json` отклоняется пустой словарь.

## Как открывается конструктор

Клавиша C ловится в `ConHotkey._unhandled_input` на любой текущей сцене. Первый раз `toggle()` вызывает `open()`: создаётся `Window` «Конструктор», в него кладётся узел из `scripts/constructor.gd` с `embedded = true`, окно вешается на корень дерева. Повторное C только показывает или прячет это окно. Сцена игры при этом не меняется.

Окно занимает правую половину экрана, игровое окно сжимается в левую. Закрытие клавишей Esc в этих скриптах не обрабатывается, хотя подпись в конструкторе это обещает.

Кнопка «КОНСТРУКТОР» в меню вызывает тот же `ConHotkey.open()` и тоже не меняет сцену. Остальные кнопки меню к конструктору не относятся.

`res://constructor.tscn` — тот же `scripts/constructor.gd` на весь экран (`embedded` остаётся false). Ни меню, ни клавиша C на эту сцену не переходят. На неё ссылается только запасной возврат из `locspace.gd`, если `Game.return_scene` пуст.

## Вкладки и смена сцены

Вкладки заданы списком `CATS` в `scripts/constructor.gd`. Смена вкладки сама по себе сцену не меняет, кроме случаев ниже.

| Вкладка | Куда ведёт | Сцена |
| --- | --- | --- |
| `chars`, `items`, `classes`, `objects`, `mats` | Инспектор полей в том же окне | нет |
| `dialogs` | `scripts/dialog_editor.gd` в правой панели | нет |
| `quests` | `scripts/quest_editor.gd` в правой панели | нет |
| `locs`, `catalog` | `scripts/loc_editor.gd` в правой панели; выбор записи включает режим правки и вызывает `ConHotkey.show_work()` | `res://work3d.tscn` |
| `map` | `scripts/global_map_editor.gd` и `scripts/map_canvas.gd` в правой панели | нет, пока не нажато «→ в 3D» |

Выбор локации на `locs` или `catalog` (`_start_edit`) запоминает путь текущей сцены в `Game.return_scene`, кладёт копию записи в `Game.edit_data`, ставит `Game.edit_loc` и `Game.edit_active`, затем меняет игровую сцену на `work3d.tscn`. Окно конструктора остаётся на корне. Кнопка «← в игру» в мастерской зовёт у конструктора `_edit_back`: при несохранённых правках спрашивает, затем `_exit_edit` возвращает `Game.return_scene` (если сцена была без пути — `res://menu.tscn`) и сбрасывает `Game.edit_data`.

`scripts/locspace.gd` (`res://locspace.tscn`) — полноэкранная оболочка того же `loc_editor.gd` для `locations.json`. Перейти на неё умеет только `constructor._open_locspace()`. Вызовов этой функции в проекте нет, поэтому с меню и с клавиши C `locspace` не открывается. Кнопка «← в игру» там возвращает `Game.return_scene` или, если он пуст, `res://constructor.tscn`.

Кнопка «В БОЙ» в `loc_editor.gd` пишет текущие данные (в отложенном режиме — сигналом `save_req` в конструктор) и меняет сцену на `res://world3d.tscn`, подставляя выбранный id в `Game.cur_loc`.

Кнопка «→ в 3D» на вкладке `map` ставит `Game.edit_world = true` и меняет сцену на `res://overworld3d.tscn`. В `_ready` этой сцены `edit_mode` берётся из `Game.edit_world`. Другого входа в режим редактора карты нет. «← назад» и Esc в этом режиме снимают `Game.edit_world`, зовут у конструктора `world_changed` и заново грузят `overworld3d.tscn` уже без редактора. На предыдущую сцену этот выход не возвращает.

В режиме редактора карты клик по точке зовёт у конструктора `world_pick`: вкладка переключается на `map` и выделяет ту же локацию. Новая точка и правка связей зовут ещё и `world_changed`, конструктор перечитывает `locations.json`.

Удаление диалога в конструкторе тоже меняет сцену на `Game.return_scene`.

На сцене `work3d` та же клавиша C, что открывает конструктор, внутри мастерской переключает режим чанков. Если выбран источник света, C вместо этого меняет его цвет. Оба обработчика сидят в `_unhandled_input` и событие не помечают обработанным, поэтому окно конструктора и действие мастерской срабатывают вместе.

`scripts/loc_grid.gd` ни одна сцена и ни один скрипт не создают. В `loc_editor.gd` поле `grid` при сборке панели обнуляется и `loc_grid.gd` не подгружается.

## Кто пишет JSON

Конструктор пишет файл текущей вкладки из `CAT_FILES` функциями `_save` и `_write_cat_file`. Папки списка («создать папку» / «удалить папку») пишутся в `res://data/groups.json`.

| Кто | Файл |
| --- | --- |
| конструктор, вкладки `chars` / `items` / `classes` / `objects` / `mats` | `data/chars.json`, `data/items.json`, `data/classes.json`, `data/objects.json`, `data/materials.json` |
| конструктор, вкладка `locs`; `loc_editor` если правка не отложена; `locspace`; вкладка `map` (`global_map_editor`); режим редактора `overworld3d` | `data/locations.json` |
| конструктор, вкладка `catalog` | `data/loc_catalog.json` |
| конструктор при создании файла; `dialog_editor` при правке | `data/dialogs/<id>.json` |
| конструктор при создании записи; `quest_editor` при правке | `data/quests.json` |
| `global_map_editor` (блок типов) | `data/loc_types.json` |
| режим редактора `overworld3d` | `data/world_terrain.json`, `data/world_decor.json`, `data/world_lights.json`, `data/world_sun.json` |

Картинки полей `image` конструктор копирует в `res://art/` и в JSON кладёт этот путь. Модель типа локации `global_map_editor` копирует так же.

На вкладках `locs` и `catalog` в режиме правки `loc_editor` файл сам не пишет: четвёртый аргумент `setup` — отложенный режим, изменения только помечают конструктор грязным. На диск попадает копия `Game.edit_data` в `_write_cat_file` (кнопки «сохранить», подтверждение выхода, кнопка «В БОЙ»). Какой файл — решает вкладка: `locs` пишет `locations.json`, `catalog` пишет `loc_catalog.json`.

`work3d` JSON не пишет. Он правит словарь `Game.edit_data` (рельеф, карта, свободные объекты, свет, точка входа) и зовёт у конструктора `on_work_dirty`. Файл появляется только когда конструктор сохраняет вкладку.

`global_map_editor` пишет `locations.json` сам, на каждое изменение точки, связи, имени, типа и копирование из выпадающего списка. Типы локаций идут отдельно в `loc_types.json`.

Режим редактора `overworld3d` пишет `locations.json` при новой точке, связях и правках точки; `world_terrain.json` при скульпте, краске и чанках; `world_decor.json` при декоре; `world_lights.json` при свете; `world_sun.json` при панели сцены.

Переименование файла диалога в `dialog_editor` копирует `data/dialogs/<старое>.json` в новое имя и, если ссылка совпала, перезаписывает `locations.json`, `quests.json` и `chars.json`.

Выпадающий список «Каталог» в `loc_editor` и списки каталога на вкладке `map` читают `locations.json`, не `loc_catalog.json`.

`scripts/terrain.gd` вызывают три редактора ландшафта и больше в этом документе не разбирается: `work3d.gd` в `rebuild`, `loc_grid.gd` в `rebuild`, режим карты `overworld3d.gd` в `_load_terrain`. `loc_grid` при этом никуда не встроен, своего JSON не пишет: он только кладёт рельеф обратно в словарь `loc` и шлёт сигнал `changed`.

## Команды work3d и loc_bridge через файлы

Обмен идёт файлами в `res://locs_edit`. Каталог создаёт `work3d`, если его ещё нет. Плагин `loc_bridge` первые 120 кадров после запуска редактора Godot файлы не читает.

«В GODOT» в мастерской:

1. `_export_tscn` собирает сцену из текущей локации (`Game.edit_loc`): меш рельефа `TERRAIN_REF`, объекты `O_<вид>_<n>`, юниты `U_<класс>_<команда>_<n>`.
2. Сцена сохраняется как `res://locs_edit/<edit_loc>.tscn`.
3. В `res://locs_edit/_cmd_open.txt` пишется этот путь.

Плагин, увидев `_cmd_open.txt`, читает путь, удаляет файл и, если сцена на диске есть, открывает её в редакторе Godot, перезагружает и выделяет корень.

«ГОТОВО (сохранить)»:

1. В `res://locs_edit/_cmd_save.txt` пишется путь `res://locs_edit/<edit_loc>.tscn`.
2. Мастерская ждёт до двух секунд файл `res://locs_edit/_save_done.txt`.
3. Плагин, увидев `_cmd_save.txt`, удаляет его, при необходимости открывает указанную сцену, вызывает `EditorInterface.save_scene()` и пишет в `_save_done.txt` строку `ok`.
4. Мастерская удаляет `_save_done.txt`, грузит `.tscn` без кэша и разбирает узлы обратно в `Game.edit_data`: `O_` (кроме `stairs`) становится свободным объектом, `stairs` — объектом сетки, `U_` — юнитом, `rocks` очищается. Если в сцене есть узлы с другими именами, в запись локации кладётся поле `decor` с путём этой сцены, иначе поле снимается.
5. На диск JSON по-прежнему пишет конструктор, не этот импорт. Если `_save_done.txt` не появился, мастерская всё равно читает `.tscn` с диска.

## Где редакторы совпадают

Один и тот же `loc_editor.gd` встроен в правую панель вкладок `locs` и `catalog` и в полноэкранный `locspace`. Сетку, лут, связи, тип и копирование «из каталога» они показывают одинаково. Отличаются файл и то, открыт ли путь: вкладки пишут `locations.json` или `loc_catalog.json` и уводят игру в `work3d`; `locspace` всегда пишет `locations.json` и из живых кнопок не открывается.

`loc_grid.gd` и `work3d.gd` оба поднимают 3D-вид локации и оба вызывают `terrain.gd`: объекты и юниты по клеткам, скульпт и краска. В игре открывается только `work3d`. Комментарий в начале `work3d.gd` называет `loc_grid` парной сеткой, но загрузчика у `loc_grid.gd` нет.

Вкладка `map` и режим редактора `overworld3d` оба правят один `locations.json`: точки, связи, имя, тип, создание и удаление локаций на карте мира. Плоский холст — `global_map_editor`, объём — кнопка «→ в 3D». Скульпт, краска, чанки, декор и свет мира пишутся уже не в запись локации, а в `world_terrain.json`, `world_decor.json`, `world_lights.json` и `world_sun.json`.

Те же четыре инструмента есть у `work3d`, но у одной локации внутри `Game.edit_data`. Общий рельеф мира и рельеф локации — разные файлы и разные входы: локация с вкладок `locs` / `catalog`, мир с вкладки `map`.

Список «Каталог» в инспекторе локации и на вкладке `map` копирует карту, лут и диалоги из записей `locations.json`. Вкладка `catalog` при этом хранит свой словарь в `loc_catalog.json`. Это второй набор локаций с тем же инспектором, не источник тех списков.
